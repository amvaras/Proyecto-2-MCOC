## Defectos encontrados y corregidos

1. **La reproducción E06 fallaba antes de ejecutar pruebas.** Se reprodujo el
   error: el inventario E06 original rechazaba .gitattributes, README.md,
   pyproject.toml y avisos de documentación E05 que habían cambiado durante
   la evolución/importación acumulativa. No era un fallo del solver. Los
   inventarios originales se conservan; ahora se comparan con revisiones
   explícitas en [AUDITORIA_CAMBIOS.json](AUDITORIA_CAMBIOS.json), con hash
   original, hash actual y motivo por archivo. Un cambio nuevo, un archivo
   ausente o un hash original incorrecto siguen produciendo error. Se adaptó
   también la comprobación heredada de E07 para mantener compatibilidad.

2. **Dossier con rutas, fecha y estados antiguos.** Mencionaba P2_E06 inexistente,
   consultas remotas de octubre, 198 pruebas y ausencia de voxelización en toda
   la versión. Se regeneró desde las métricas actuales, se aclaró el alcance
   de E06 dentro de E07 y se incorporaron rutas reproducibles. Se conserva
   el documento anterior sin modificar sus bytes.

3. **Contador demasiado permisivo y commit bloqueado.** Excluía también código
   y ecuaciones del conteo, aunque la excepción oficial solo menciona figuras
   y tablas. Además exigía literalmente el marcador de commit pendiente,
   impidiendo reemplazarlo por un SHA. Se corrigieron ambos comportamientos;
   se validan figuras PNG, enlace al IFC, cobertura de la matriz, enlaces y
   caracteres de control. El modo --require-published rechaza un pendiente;
   aceptar el formato de un SHA no demuestra su existencia remota.

4. **Huellas del manifiesto tomadas antes del cierre.** La generación inspeccionaba
   el enlace a e06.json mientras su estado aún era running. El verificador ahora
   vuelve a congelar los enlaces después de guardar el estado final, para que
   las huellas correspondan a los archivos entregados.

5. **Acceso a la ejecución.** Se añadió [E06.md](../../E06.md) y
   [VERIFICAR_E06.ps1](../../VERIFICAR_E06.ps1). El lanzador ejecutado usa el
   entorno instalado, conserva salidas anteriores y propaga errores.

La primera instalación independiente falló por las llaves del nombre de una
carpeta temporal protegida del entorno de ejecución: setuptools las interpretó
como una variable. Se conservó el log y, con la autorización solicitada, se
repitió el mismo procedimiento en la carpeta temporal normal de Windows.
La repetición aprobó; no se alteró el solver ni se omitió la instalación.

Se añadieron **15 pruebas de regresión** en test_e06_auditoria.py. No se
reescribieron thermal_nd.py, diffusion_1d.py, el IFC ni los módulos de E07.
Las pruebas y evidencias E05 anteriores se conservan como registros de esas
ejecuciones; sus conteos y hashes no se sustituyen retrospectivamente.
